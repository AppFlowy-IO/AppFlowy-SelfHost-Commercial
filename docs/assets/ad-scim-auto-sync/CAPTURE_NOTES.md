# Entra setup screenshots

Captured from the real Microsoft Entra admin center on October 9, 2026, for
[the AD and Entra guide](../../AD_SCIM_AUTO_SYNC.md#using-microsoft-entra-id-instead).
These are setup references, not evidence of successful Entra-to-AppFlowy sync.

| File | Captured state |
| --- | --- |
| `01-entra-provisioning-overview.png` | Initial provisioning overview for an existing application; provisioning had not been configured |
| `02-entra-credentials.png` | New configuration form with empty Tenant URL and Secret token fields |
| `03-entra-group-license-required.png` | Actual plan restriction under the application's Add user/group action |
| `04-entra-non-gallery-application.png` | Unsubmitted application form with the example name AppFlowy SCIM Demo |

All four images are element screenshots cropped by the browser at capture time.
They exclude the account header, tenant domain and IDs, user names, user rosters,
and browser address bar. No credentials were entered for these captures; no
provisioning configuration, application, or assignment was saved. The temporary
Automatic-mode selection was discarded. The existing application label
AppFlowy SSO is visible only to identify the portal page; it does not mean that
SAML sign-in was configured or verified as part of this walkthrough.

The PNGs contain no text or EXIF metadata. Their interface content has not been
replaced or generated. The guide labels the application form as unsubmitted and
explains the license and network requirements still needed for a live recording.
